A relocation is evidence of the segment value, while the code path is evidence of the use.

## Formats and code paths

- **ICE! streams.** The routine at image offset `00605D` checks `ICE!`, reads big-endian endpoint/output fields, decodes backward, and writes output backward. Its bit helpers are at `0060DA` and `0060E7`; token selection is at `006099`, with match copy at `006176..00618A`. Loader callers at `001F68..001FB3` process streams `2BF6`, `2D9A`, `2F9E`, and `2FB7`. These declare `FD00h`; `1A38` declares `7D00h`. The all-zero `0A67` frame is the decode destination. Wrapper code at `006031` copies 768 bytes from output offset `FA00h` to a palette buffer, so the `FD00h` output has 64,000 indexed pixels followed by 256 RGB triples. A one-time retained Unicorn run of the original routine produced a recognizable 320x200 chunky title scene for `2BF6` (`build/workers/data/png/emu_ref_2bf6_chunky.png`). It has not been matched by the Python transcription: the Python version produces the declared 32,000 bytes for `1A38` but its candidate image is noise, and it overruns the output boundary on the four `FD00h` streams. Do not treat those Python buffers as verified decodes.
- **ICE! trailing bytes.** All bytes after each endpoint through the next frame boundary are zero: `1A38` has 12 bytes (`01E1E4..01E1EF`), `2BF6` has 7 (`02D999..02D99F`), `2D9A` has 1 (`02F9DF`), `2F9E` has 15 (`02FB61..02FB6F`), and `2FB7` has 3 (`0325AD..0325AF`). These are consistent with alignment fill; the bytes do not identify which linker stage inserted them.
- **Packed graphics and VGA.** The far-pointer table at `0059CA..0059DE` names frames `1E1F`, `37A7`, `438A`, `4E83`, and `5B63`; its final two pointers are offsets `035A` and `0000` into `5B63`. The renderer at `0059E4` reads a source far pointer from `DS:009B`, selects plane masks 1, 2, 4, and 8 through Sequencer port `3C4h`, and copies four source bytes per destination byte for each `CX` iteration. This establishes four-plane copying but not bank dimensions or object boundaries. A separate palette routine at `006222..006245` writes RGB triples through VGA DAC ports `3C8h/3C9h`; the exact source pointer used by that routine was not tied to the 768-byte `2BC6` block. That block contains 256 triples whose channel values are all 0..63, making it a plausible 6-bit DAC palette, but remains a hypothesis.
- A trial interpretation of the first four raw banks as consecutive 16x16, four-plane tiles produced candidate sheets under `build/workers/data/png/bank_*_tiles16_planar_candidate.png`; none is recognizable as tiles or sprites. Treat those PNGs as a failed layout hypothesis. The pointer table and renderer establish access and plane-copy behavior, but do not provide tile dimensions or prove that the banks contain tile records.
- **ADLX sound data.** The music resource starts carry `ADLX` and tagged blocks `AHDR`, `IMAP`, and `TRCK`. Game call sites pass segment values to C functions at offsets `0F88` or `1852` (linear C addresses `9708` and `9FD2` respectively). C code at `9708` enters the sound module, sets `ES=0664`, and calls sound functions at `0664:1331` and `0664:134E`; the sound routines are the consumers. The tagged shape supports an AdLib tracker/register stream, but register event layout, tick rate, and any PCM sample format are not proven. The `smpl.UGH!-All_Sounds` Amiga file is 30,596 bytes and TFMX data is separate; no direct DOS match is established.
- **VGA plane copying.** Game code at image offset `0059E4` selects plane masks through `3C4h`, reads the source pointer stored at `DS:009Bh`, and writes bytes to the VGA memory target in `ES:DI`. Image offset `005A1A` copies 192 words from a far pointer to two destinations. These sites are direct VGA evidence, but they do not identify a single canonical image size for the large raw banks.

## DGROUP strings and tables

DGROUP starts at image `05C090` (file frame `5C09`) and spans `7E2Eh` bytes. The first two Borland runtime strings occur at `+002F` (`Divide error`) and `+003D` (`Abnormal program termination`). The game-content candidate starts at `+00EE`; the runtime boundary ownership is not yet established, so `+00EE` is a content boundary supported by the first game string, not a confirmed ownership boundary.

- `+00EE..+091F`: NUL-terminated level-name sequence (first `CAVITY`, then `FIRSTCOMMUNION`, `FIGURATIVETHEATRE`; last `ASADSADNESSSONG`). Individual names are visible as printable strings, but their stride and linkage to the level records are not established.
- `+0920..+0AE3`: credits text. Includes "PROGRAMMED", Mario Knezovic, Carsten Neubauer, "ORIGINAL AMIGA VERSION", Thomas Klinger, Bjorn Roy (ASCII bytes read as `RN ROY` in one context), graphics, music/FX, level-design, and thanks credits.
- `+0AE4..+0CF0`: menu, password prompt, player/control/difficulty labels, level label, game-result messages, and high-score defaults. Defaults at `+0C86`, `+0C9B`, `+0CB0`, `+0CC5`, `+0CDA` are FRED/20000, BARNEY/10000, WILMA/5000, PEBBLES/2500, KALKI/1000.
- `+0CF1..+3D39`: binary data and strings including `UGH!.HI`; exact object layout and password table location are unresolved. Passwords are known to be stored in clear text from prior evidence, but this scan did not isolate their records.
- `+3D3A..+764B`: level title / instruction text mixed with binary fields. Text includes "INTRODUCING PLATFORMS", "DINO AND THE BIRD", "ELEVATOR ACTION", "FUNNY WATER", "TOWER OF ATLANTIS", and later level-specific messages. The bytes resemble related content in Amiga `Texts.lo5`, but no structured mapping is proven.
- `+764C..+7E2D`: opaque tail tables; repeated values look coordinate-like, but record boundaries and consumers remain unknown.

## Amiga comparison

The OFS ADF was parsed and the files were extracted under `build/workers/data/amiga/`. The disk includes `Blocks.lo5` (24,744 bytes), `Font.lo5` (8,572), `Mann.lo5` (9,158), `Frau.lo5` (8,074), `dino.lo5` (3,698), `bird.lo5` (6,790), `baum.lo5` (2,524), `stein.lo5` (1,336), `Wasser.lo5` (694), `bubbles.lo5` (8,258), `TriOpt.lo5` (19,872), `ScoreBoard.lo5` (2,786), `ScoreBoard2.lo5` (3,106), `title.lo5` (8,812), `Texts.lo5` (3,632), `Demo.lo5` (752), and `DemoData` (246). Their `.lo5` streams begin with `JOKE`, unlike DOS `ICE!` objects. The Amiga resources were not decoded; names and sizes are semantic clues only. Extracted files remain build artifacts, and the ADF itself was not modified.
