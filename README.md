# Ugh! reconstruction

Reconstruction of the DOS game Ugh! (Ego Software / Play Byte, 1992) from `UGH.EXE`.

Status: **full-file proof reached.** `python tools/verify.py` builds the whole program from
source with Borland C++ 3.0, TASM 3.0 and TLINK 5.0 plus the original `C0H.OBJ` and `CH.LIB`,
and PKLITE 1.15 packs the result into the original `UGH.EXE`, byte for byte.

| Class | Bytes | State |
|---|---:|---|
| Hand assembly (game, sound, timer) | 25,885 code + 4,584 data | exact, mechanical labels |
| Compiled C (music and sample front end) | 7,074 | exact, 23 functions, mechanical names |
| Borland runtime | 5,048 code + 834 data | linked from the original library |
| Data (far banks, game data in DGROUP) | 365,818 | raw `db` modules: debt |

Known debt:

- The data modules in `src/data/` are generated byte dumps without structure or meaning.
- Relocation order is reproduced by a reproducing layout, not a recovered one: GAME and SOUND
  are cut into 32 and 14 segment fragments declared in emission order (`src/data/LAYOUT.ASM`
  fixes physical order), and 23 short jumps across fragments carry a `+1` addend for a TLINK
  quirk. Commit `6776f37` has the plain one-segment-per-module sources, which match the image
  and the relocation set but not the table order. See `docs/link.md`.
- No semantic names yet; no portable C translation yet.

```
python tools/oracle.py      # original file, expansion and repack against the lock
python tools/verify.py      # fresh build, compared with the expanded and the packed original
python tools/asmverify.py   # assembly contributions in isolation
python tools/cjudge.py      # C functions in isolation
python tools/libmatch.py    # runtime attribution
python tools/census.py      # coarse region table (boundaries predate the exact extents)
```
